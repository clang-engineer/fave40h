# 원본 4레이어 펌웨어 복원 현황과 남은 범위

기록일: 2026-10-23

## 결론

**완성 직전이나 단순 마무리 단계가 아니다. 현재 결과물은 기기에 사용할 수 있는 펌웨어가 아니라 빌드가 차단된 실험용 복원 소스다.**

목표는 제조사 원본 `firmware/origin/FAve40H_VIAL.uf2`의 동작을 재현하는 QMK/Vial 구현이다. 과거 6레이어 포팅이나 제조사 8레이어 펌웨어와는 별도 작업이다. 기존 [roadmap.md](roadmap.md)는 과거 6레이어 포팅 내용이므로 이 문서와 구분한다.

## 현재 확인된 진척

- 원본의 USB 식별값, 키 매트릭스·GPIO, LED 배치, 공장 키맵과 저장 구조 등의 근거를 복구했다.
- 일부 커스텀 키 동작과 RGB 동작을 원본 Thumb 명령 실행 및 고정된 Vial-QMK 후보 소스와 비교했다.
- 최근에는 선택된 RGB 효과의 실제 task 진입 → STARTING → RENDERING/후처리 → **다음 호출의 FLUSHING**을 연결했다. 렌더 후 mode/enable/suspend가 바뀌면 flush 시점에 효과를 다시 선택하는 동작도 확인했다.
- 마지막 검증은 **단위 테스트 286개**, 읽기 전용 원본 에뮬레이션 **16개 fixture / 20,804개 사례**를 통과했다. 생성 대상 파일 11개와 원본 복구 산출물 21개의 결정적 재생성 검사도 통과했다.

**테스트 개수는 검증량이지 완성률이 아니다.** 선택된 코드 경로의 호스트·에뮬레이션 검증은 전체 펌웨어 빌드, 실제 MCU 실행, USB·저장장치·LED의 물리 동작을 증명하지 않는다. 후보 소스가 제조사의 실제 소스나 동일 리비전이라는 뜻도 아니다.

상세 근거와 각 검증의 경계는 [원본 대상 README](../keyboards/fave40h_original/README.md)와 [원본 복구 README](../original-vial/README.md)에 기록한다.

## 완성까지 남은 큰 범위

### 1. 전체 동작 연결과 동등성 검증

- RGB의 나머지 43개 효과에 대한 동등성 검증. 후보 구현이 존재하는 것과 원본과 같다고 검증된 것은 다르다.
- RGB SYNCING, 저장·시간 게이트, 전체 task/스케줄러/scan/feature 경로 연결. 현재는 프레임 시작을 시험 입력으로 지정하며 SYNCING 분기는 실행하지 않는다.
- Vial 잠금·보안, 키 처리·탭·override·report 경로 및 전체 기능 통합.
- 파괴적 초기화 명령 `0x7E0F`를 포함한 초기화·리셋 연결과 안전성 확인. 파괴적 본체는 실행하지 않았다.

### 2. 저장 안전성과 기존 데이터 호환성

- EEPROM 에뮬레이션의 저장·재생·복구·통합 경로 완성.
- 초기화, 빌드 식별값, 기존 설정 유지·이관의 호환성 확인.
- 논리 저장 영역과 물리 erase sector 크기가 다른 데 따른 인접 영역 보존 문제 해결.

이 부분이 잘못되면 설정 손실이나 저장 영역 손상이 발생할 수 있으므로, 일부 저장 모델 테스트 통과만으로 안전하다고 판단하면 안 된다.

### 3. 실제 빌드와 하드웨어 검증

- 전체 QMK/ChibiOS 펌웨어 컴파일·링크. 기존의 호스트 프로브나 제한된 ARM 재배치 가능 객체는 완성 펌웨어가 아니다.
- 정확한 MCU·용량·발진기·전기적 동작과 부트로더·복구 방법 확인.
- 별도 승인 후 실제 보드의 USB, 키 입력, 저장 유지, RGB·타이머·DMA 및 복구 동작 검증.

현재 필요한 GNU Arm/QMK 도구 일부가 없으며, 설치는 승인되지 않았다. 전체 빌드와 기기 검증은 아직 수행하지 않았다.

## 기간 추정과 불확실성

- **몇 시간 더 작업하면 끝나는 상태가 아니다.**
- 대화에서 제시한 규모감은 **주 단위 추가 작업까지 예상해야 한다**는 것이었다. 이는 상세 작업량 산정에 근거한 일정이나 완료 약속이 아니라 거친 추정이다.
- 현재 근거로는 신뢰할 만한 완료 날짜나 완성률을 제시할 수 없다. 몇 주 안에 반드시 완성된다거나, 특정 기간이 상한이라는 뜻이 아니다.
- 원본의 미확인 경로, 저장 안전성 문제, 전체 빌드 결과, 하드웨어 차이 및 필요한 승인에 따라 범위와 기간이 달라질 수 있다.

계속할 경우 세부 검증 수를 진척률처럼 보고하지 말고, 위 세 범위의 종료 조건·미확인 사항·중단 판단을 먼저 명확히 해야 한다.

## 현재 중단 상태와 안전 경계

사용자가 작업 기간을 질문한 뒤 자동 작업 루프를 중단했다. **이번 문서화 요청은 구현·검증 루프 재개 승인이 아니다.**

- `ORIGINAL_TARGET_INCOMPLETE`의 무조건 빌드 차단을 유지한다.
- 현재 펌웨어는 사용 가능하거나 flash-ready한 것으로 취급하지 않는다.
- 과거 승인된 커밋·푸시는 `95f4776`에서 완료됐다. 이 문서 최초 작성 당시 이후 검증 변경은 미커밋 상태였다. 이후 사용자가 이번 복원·검증 작업과 현황 문서 전체의 커밋·푸시를 별도로 승인했다. 이는 구현 루프 재개나 향후 변경의 자동 커밋 승인이 아니다.
- 이번 추가 검증 작업에서는 도구 설치, 실제 EEPROM 초기화·이관, USB/기기 테스트 또는 플래시를 하지 않았다.
- 후속 구현, 빌드 도구 설치, 저장·기기 작업, 빌드 차단 해제 및 배포는 각각 해당 범위의 확인·승인이 필요하다.
